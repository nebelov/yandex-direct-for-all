# Yandex Direct For All

Набор навыков и серверов MCP для работы с Яндекс Директом из Claude Code и Codex. Агент с этим набором читает кабинет, собирает спрос в Wordstat и выдачу конкурентов, разбирает поисковые запросы и площадки РСЯ, готовит сборку кампаний и вносит правки в кабинет — только по вашему явному разрешению и с проверкой результата.

Всё, что нужно для старта, — аккаунт Яндекса с доступом к Директу. Приложение для авторизации создавать не надо: оно уже встроено. Остальные источники (Метрика, Yandex Cloud, XMLRiver, Roistat, amoCRM, Битрикс24) подключаются по мере надобности.

## Что внутри

### Навыки

Главный навык — `yandex-direct-unified`. Агент начинает с него любую задачу по Директу: в нём порядок работы, правила решений и ссылки на подробные справочники. Остальные навыки он открывает сам, когда задача их касается.

**Директ, спрос и выдача**

| Навык | Для чего |
|---|---|
| `yandex-direct-unified` | Единый порядок работы: вводные клиента, доступ, снимок кабинета, семантика, сборка, запись, проверка |
| `yandex-wordstat` | Справочник Wordstat второго поколения: методы, квоты, нулевой спрос, операторы |
| `xmlriver-serp-research` | Выдача Яндекса и Google и Wordstat через XMLRiver — альтернатива Yandex Cloud |
| `commercial-demand-research` | Оценка спроса в нише и регионе до рекламной семантики |
| `keysso-competitor-research` | Реклама конкурентов из Keys.so |
| `serp-rank-verification` | Проверка позиций в выдаче |
| `direct-report-wizard-library` | Набор из 20 сохранённых отчётов в Мастере отчётов Директа |
| `yandex-cloud-search-cost-control` | Расследование расходов платного поиска Yandex Cloud |

**CRM и продажи** — подключаются, только если у клиента они есть

| Навык | Для чего |
|---|---|
| `roistat-reports-api` | Отчёты Roistat, сверка с сырыми сделками, коллтрекинг |
| `amocrm-api-control` | Доступ к amoCRM, схема воронок, сверка заявок |
| `bitrix24-crm-api` | Чтение CRM Битрикс24: лиды, сделки, звонки, история стадий |
| `bitrix24-bi-reports` | BI Конструктор Битрикс24: наборы данных, графики, дашборды |

**Качество данных и отчётов**

| Навык | Для чего |
|---|---|
| `analytics-dashboard-integrity` | Проверка цифр дашбордов и выводов по ним |
| `structured-output-file-integrity` | Целостность выгрузок TSV, CSV и JSON |
| `google-sheets-live-guard` | Безопасная правка живых Google Таблиц |
| `work-status-reporting` | Честные статусы работ без «готово» раньше времени |
| `client-communications-research` | Разбор звонков и переписки клиента: возражения, язык покупателя |

`yandex-performance-ops` и `yandex-direct-client-lifecycle` — библиотеки скриптов, шаблонов и плейбуков, на которые ссылается единый навык.

### Серверы MCP

Подключаются вместе с плагином:

- **yandexDirect** — чтение Директа (`yd_api`). Только метод `get` по закрытому списку служб: кампании, группы, объявления, ключевые фразы, ставки, быстрые ссылки, уточнения, отчёты. Писать в кабинет этот сервер не умеет.
- **yandexWordstat** — Wordstat через Yandex Cloud: `top-requests`, `dynamics`, `regions`, `get-regions-tree`, `get-region-children`. Ведёт общий учёт лимита: 10 запросов в секунду и 100 тарифицируемых в час.
- **yandexSearch** — платный поиск Yandex Cloud. По умолчанию выключен и без отдельного разрешения не сделает ни одного запроса.

### Скрипты

Лежат в `plugins/yandex-direct-for-all/scripts/` и в папках навыков. Главные:

- `start_yandex_user_auth.sh` — вход в Директ и Метрику через встроенные приложения
- `collect_wordstat_wave.sh`, `collect_organic_serp.sh`, `collect_ad_serp.sh` — сбор Wordstat и выдачи через Yandex Cloud или XMLRiver
- `collect_direct_cabinet_snapshot.py` — снимок структуры кабинета и поисковых запросов по кампаниям клиента
- `direct_write_gate.py` — единственный путь записи в Директ
- `metrika/*.sh` — счётчики, цели, конверсии и источники Метрики

Полный указатель с параметрами — [script-index.md](plugins/yandex-direct-for-all/skills/yandex-direct-unified/references/script-index.md).

## Установка

Нужны `uv`, Node.js 20+ и npm: через них запускаются серверы MCP.

Claude Code 2.1.275 и новее — одной командой в окне Claude Code:

    /plugin install yandex-direct-for-all --marketplace nebelov/yandex-direct-for-all

Claude Code 2.1.78–2.1.274:

    /plugin marketplace add nebelov/yandex-direct-for-all
    /plugin install yandex-direct-for-all@yandex-direct-for-all

Codex — добавить маркетплейс и установить плагин в интерфейсе Codex:

    codex plugin marketplace add nebelov/yandex-direct-for-all

Без маркетплейса — из клона хранилища. Первая команда только показывает план, вторая устанавливает:

    bash plugins/yandex-direct-for-all/scripts/install_bundle.sh --target both
    bash plugins/yandex-direct-for-all/scripts/install_bundle.sh --target both --apply

Установщик выдаст номер запуска, команду отката и готовые команды подключения серверов MCP. Ваши правленые файлы он не перезаписывает: если навык с тем же именем уже стоит вручную, установка остановится с конфликтом.

## Подключение доступов

Команды запускайте из папки проекта клиента: токены лягут в её `.codex/auth/` с правами `0600`.

### Директ

Найти скрипт авторизации (после установки из маркетплейса):

    AUTH="$(find ~/.claude/plugins ~/.codex/plugins -path '*yandex-direct-for-all*' -name start_yandex_user_auth.sh 2>/dev/null | head -1)"

Войти:

    bash "$AUTH" --service direct --client-login 'логин-рекламодателя'

Рекламодатель указывает свой логин, представитель агентства — логин клиента. Откроется страница согласия Яндекса с выбором аккаунта, после неё скрипт сам проверит доступ чтением.

Чтобы сервер MCP Директа увидел токен, создайте файл `.codex/direct-access.json` с правами `0600`:

    {"environment": "production", "token_file": "auth/direct_oauth_token.json", "client_login": "логин-рекламодателя"}

и запускайте Claude Code или Codex из терминала, где задано:

    export YANDEX_DIRECT_ACCESS_FILE="$PWD/.codex/direct-access.json"

Без этого файла сервер работает с песочницей Директа и пишет, какой переменной не хватает.

### Метрика

    bash "$AUTH" --service metrika

Токен ляжет в `.codex/auth/metrika_oauth.env`. Скрипты Метрики найдут его, если задать:

    export YANDEX_METRIKA_CONFIG_FILE="$PWD/.codex/auth/metrika_oauth.env"

### Wordstat и выдача: Yandex Cloud или XMLRiver

Подходит любой из двух путей.

**Yandex Cloud.** Создайте вне хранилища файл с правами `0600`:

    {"api_key":"...","folder_id":"..."}

Проверка и сбор:

    plugins/yandex-direct-for-all/skills/yandex-performance-ops/scripts/wordstat_tool.sh preflight /путь/к/файлу.json
    plugins/yandex-direct-for-all/scripts/collect_wordstat_wave.sh --provider yandex-cloud --masks-file masks.tsv --output-dir result --config /путь/к/файлу.json

Серверу MCP Wordstat нужны переменные `YANDEX_WORDSTAT_API_KEY` и `YANDEX_WORDSTAT_FOLDER_ID`.

**XMLRiver.** Задайте `XMLRIVER_USER` и `XMLRIVER_KEY` — сборщики выберут XMLRiver сами. Для пробы без своего ключа есть общий демо-доступ `--use-demo-key`: не дороже 2 ₽ за запуск. Сбор идёт в три шага: `plan` считает запросы и цену, `collect` выполняет только одобренный план с потолком стоимости, `export` собирает таблицы. Подробности — в [навыке](plugins/yandex-direct-for-all/skills/xmlriver-serp-research/SKILL.md).

Если заданы оба доступа или доступ передан файлом, укажите путь явно: `--provider yandex-cloud` или `--provider xmlriver`. Молча переключаться между платными сервисами сборщики не будут.

### Roistat, amoCRM, Битрикс24

Необязательны. Без них агент работает по Директу и Метрике, а выводы о продажах помечает «продажи не проверены». Как подключить каждый — в навыках `roistat-reports-api`, `amocrm-api-control` и `bitrix24-crm-api`.

## Как этим пользоваться

Пишите агенту задачу обычными словами. Он сам откроет `yandex-direct-unified`, соберёт вводные и пойдёт по порядку. Примеры:

- «Сделай аудит кампаний клиента за 30 дней: что режет бюджет и что масштабировать»
- «Разбери поисковые запросы за неделю и предложи минус-слова»
- «Найди площадки РСЯ, которые тратят деньги без заявок»
- «Оцени спрос на услугу в Казани и покажи сегменты»
- «Собери рекламу конкурентов по нашим ключам и покажи, чем отстроиться»
- «Собери семантику и структуру кампаний для нового клиента»
- «Сверь заявки из Метрики со сделками в CRM»

### Порядок работы

1. **Вводные.** Агент заполняет короткую форму «поле = ответ»: что продаём, кому, где, какая заявка хорошая, что нельзя рекламировать. Ответ «не знаю» он принимает и больше не переспрашивает.
2. **Доступ.** Проверяет свежим запросом, что токен видит нужный кабинет. В общем агентском аккаунте читает только кампании этого клиента.
3. **Снимок кабинета.** Структура, поисковые запросы, площадки, цели Метрики — до любых выводов.
4. **Исследование.** Wordstat волнами, синонимы, выдача и реклама конкурентов, отзывы, задачи покупателей.
5. **Решения.** Каждую строку спроса разбирают построчно: включить, исключить, отложить или нужна новая посадочная. Скрипты собирают и проверяют таблицы, но смысловых решений не принимают.
6. **План изменений.** Точные объекты, значения «до» и «после», стоимость операций, способ отката.
7. **Запись.** Только после вашего «да» на конкретный пакет и только через `direct_write_gate.py`.
8. **Проверка.** Агент перечитывает кабинет и сравнивает каждое затронутое поле с планом.

### Что агент не сделает без вашего разрешения

Не изменит ставки, бюджеты и стратегии. Не добавит минус-слова, не исключит площадки, не заменит объявления. Не отправит объявления на модерацию, не запустит и не остановит кампании. Бюджет и денежные параметры стратегии он берёт только из вашего решения: пока решения нет, в плане стоит «бюджет не задан».

## Что работает без отдельных источников

| Нет источника | Что остаётся | Что недоступно |
|---|---|---|
| Метрика | Директ, спрос, конкуренты | Цели и конверсии с сайта |
| Yandex Cloud | Всё, если подключён XMLRiver | — |
| Yandex Cloud и XMLRiver | Директ, Метрика, CRM | Wordstat и выдача |
| Roistat и CRM | Директ и Метрика | Продажи и окупаемость: помечаются «не проверены» |

## Безопасность и данные

- Токены, коды подтверждения и ключи не передаются в командной строке и не печатаются.
- Токены и выгрузки клиента хранятся только в его проекте, в закрытых папках вне каталога навыков.
- Встроенные идентификаторы приложений Яндекса открыты намеренно: секретов приложений и чужих токенов в хранилище нет.
- Демо-ключ XMLRiver общий для всех, поэтому для работы с клиентом заведите свой.
