# Отчёты Roistat

## Доступ

Адрес проекта, номер проекта и ключ берутся только из защищённой настройки текущего пользователя. Ключ не передаётся аргументом процесса и не выводится. Примеры используют PROJECT_ID и синтетические данные.

## Чтение

1. Получить доступные отчёты и их схему.
2. Запросить analytics/data по точному периоду, срезам и модели атрибуции.
3. Пройти всю постраничную выдачу; частичная страница не считается полным отчётом.
4. Для продаж и заявок сверить агрегаты с integration/order/list и связанной информацией о визите.
5. Сохранить параметры запроса, исходные страницы, объединённые строки и контрольные суммы.

## Проверка

- Формула и тип каждой пользовательской метрики должны читаться обратно.
- Процентные показатели имеют тип percent.
- Модели атрибуции сравниваются по фактическим числам, а не по названию.
- Позднее событие CRM может относиться к более старому визиту; такое расхождение объясняется отдельно.
- Источник логики указывается понятным названием: системный расчёт Roistat, отметка CRM или сверка истории.

## Запись

Существующий отчёт не меняется без отдельного явного разрешения. Новый сохранённый отчёт сначала создаётся с уникальным названием, затем читается обратно. Любая запись проходит общие ворота yandex-direct-unified и имеет подготовленный откат.

## Результат

Пакет содержит manifest.json, request.json, raw-pages/, rows.jsonl, reconciliation.tsv и validation.md. Токен, частные контакты и локальные пути в публичный отчёт не включаются.
